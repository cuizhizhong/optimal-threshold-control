# 长时域数值修订核查

## 实际运行与结果

MATLAB R2025b、仓库自带 OpenOCL/CasADi、IPOPT 3.12.3（MUMPS）。参数为 `p=0.5, c=2, gamma=0.3, K=0.15`，统一 `T=300, d=2`；原始动力学、线性成本、状态及控制约束不变，无终端约束或正则化。

| 算例 | 最终 N | 解析成本 | OpenOCL 成本 | 重积分容量超出量 | 实际阶段 |
|---|---:|---:|---:|---:|---|
| E1 | 4000 | 0.416185914776 | 0.416205009097 | 2.97e-7 | 0 → 1 → 0 |
| E2 | 8000 | 1.529511160151 | 1.529523361398 | 7.99e-7 | 0 → q_B → 1 → 0 |
| E3 | 4000 | 0.433981007323 | 0.433998516352 | 4.80e-8 | 1 → 0 |
| E4 | 8000 | 1.268834778342 | 1.268831095584 | 7.70e-7 | q_B → 1 → 0 |
| E5 | 4000 | 0.536233196705 | 0.536256361592 | 5.57e-8 | 1 → 0 |

五例均返回 `Solve_Succeeded`。最大成本相对差异约 `0.00459%`，最大状态重积分差异约 `8.6e-8`，最后 20 个时间单位的原始控制为 0。终端零控制延拓检查通过；极小正感染量保留在峰值计算中，不因浮点相消变为 0。

- E2/E4 的 `N=4000` 原始结果保存在 `data/numerical_scenarios/coarse/`，容量重积分偏差超过 `1e-6`，因此主图表采用 `N=8000`。没有通过放宽验收容差或裁剪状态来消除超限。
- `checks/E2.mat` 保存 E2 的同一次加密结果；它与主 E2 一致，不是另一项独立优化实验。
- `checks/E1.mat` 使用常值 `q=0.7` 的控制及其积分状态初始化，实际经过 1621 次 IPOPT 迭代收敛。与解析初猜求解的控制最大差异约 `6.34e-13`。
- 原 `CUI_q.m` 无参数运行成功，原脚本未改动。独立保存的旧基准完整区间成本为 `1.529525451659`；脚本打印的 `trapz` 成本保留原样，不用于新表格。
- 诊断时试过将 IPOPT `bound_relax_factor` 设为 0，长尾求解明显变慢后中止；最终沿用原默认值 `1e-8`，原模型边界仍按 `1e-6` 目标独立核查。另保存了标准边界和自适应障碍参数的 E2 诊断输出；后者不作为主图表来源。
